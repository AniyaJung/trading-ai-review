# 历史方案与记录

本目录是项目历史档案，不是当前产品文档。文件保留了当时的上下文、设计判断、实施步骤和验证结果，便于追溯；其中的分支名、测试数量、数据库版本、功能缺口、优先级和下一步建议可能已经过期。

当前说明请从 [文档索引](../README.md) 开始。

## 目录内容

| 路径 | 性质 | 使用方式 |
| --- | --- | --- |
| `specs/` | 历史设计规格 | 理解早期产品目标和设计取舍 |
| `plans/` | 已执行或阶段性实施计划 | 追溯任务拆分，不作为当前待办 |
| `2026-06-10-next-conversation-context.md` | 历史会话交接 | 了解当时状态，不直接照搬“下一步” |
| `2026-06-12-architecture-optimization-backlog.md` | 滚动架构记录 | 查看演进过程；完成状态和优先级可能失效 |
| `packaging-verification.md` | 阶段性打包验证日志 | 查看旧验证证据；当前状态以 `docs/packaging.md` 为准 |

## 资料状态

- 历史规格和计划原则上保留原文，不回写成当前实现。
- 某个历史计划完成，不表示所有验收项在现在仍然通过。
- 需要重新启动工作时，先检查当前代码与 `docs/` 根目录，再从历史文件提取仍然适用的约束。
- 新的阶段性方案可以继续放入本目录，但必须带日期，并在当前文档中记录最终落地结果。
